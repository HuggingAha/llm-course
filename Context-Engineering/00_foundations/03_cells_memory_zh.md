# 细胞：引入记忆与状态

> “我们就是我们的记忆，我们是那个变幻莫测的博物馆，是破碎镜子的堆积。”——博尔赫斯

## 从分子到细胞

我们已经探讨了**原子**（单条指令）和**分子**（带示例的指令）。现在我们进入**细胞**——带有**记忆**、可在多轮交互中持续存在的上下文结构。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│  细胞 = [指令] + [示例] + [记忆/状态] + [当前输入]                          │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

就像生物细胞在与环境互动时保持内部状态一样，我们的上下文“细胞”在与 LLM 多轮交互中保留信息。

## 记忆问题

默认情况下，LLM 没有记忆。每次请求都是独立处理的：

```
┌───────────────────────┐      ┌───────────────────────┐
│ 请求 1                │      │ 请求 2                │
├───────────────────────┤      ├───────────────────────┤
│ “My name is Alex.”    │      │ “What's my name?”     │
│                       │      │                       │
└───────────────────────┘      └───────────────────────┘
          │                              │
          ▼                              ▼
┌───────────────────────┐      ┌───────────────────────┐
│ 回复 1                │      │ 回复 2                │
├───────────────────────┤      ├───────────────────────┤
│ “Hello Alex, nice     │      │ “I don't have access  │
│  to meet you.”        │      │  to previous          │
│                       │      │  conversations...”    │
└───────────────────────┘      └───────────────────────┘
```

没有记忆，LLM 会忘记之前的交互信息，导致体验割裂且令人沮丧。

## 细胞方案：对话记忆

最简单的细胞结构是在上下文中加入对话历史：

```
┌───────────────────────────────────────────────────────────────────────┐
│                                                                       │
│  系统提示: “You are a helpful assistant...”                           │
│                                                                       │
│  对话历史:                                                            │
│  用户: “My name is Alex.”                                             │
│  助手: “Hello Alex, nice to meet you.”                                │
│                                                                       │
│  当前输入: “What's my name?”                                          │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

现在 LLM 能访问之前的对话，实现上下文连贯。

## 记忆 Token 配额问题

随着对话增长，上下文窗口会被填满。我们需要记忆管理策略：

```
          [上下文窗口 Token 数]
          ┌─────────────────────────────────────────────┐
          │                                             │
回合 1    │ 系统指令               用户输入 1           │
          ├─────────────────────────────────────────────┤
回合 2    │ 系统    历史 1         用户输入 2           │
          ├─────────────────────────────────────────────┤
回合 3    │ 系统  历史 1  历史 2   用户输入 3           │
          ├─────────────────────────────────────────────┤
回合 4    │ 系统  历史 1-3           用户输入 4         │
          ├─────────────────────────────────────────────┤
回合 5    │ 历史 2-4                用户输入 5          │
          └─────────────────────────────────────────────┘
                                       ▲
                                       │
                        最终必须舍弃部分内容
```

## 记忆管理策略

有多种策略可优化有限上下文窗口的利用：

```
┌───────────────────────────────────────────────────────────────────┐
│ 记忆管理策略                                                     │
├────────────────────┬──────────────────────────────────────────────┤
│ 窗口滑动           │ 只保留最近 N 轮对话                          │
├────────────────────┼──────────────────────────────────────────────┤
│ 总结压缩           │ 将较早的对话轮压缩为摘要                      │
├────────────────────┼──────────────────────────────────────────────┤
│ 键值存储           │ 重要事实单独提取并存储                        │
├────────────────────┼──────────────────────────────────────────────┤
│ 优先级剪枝         │ 优先移除不重要的对话轮                        │
├────────────────────┼──────────────────────────────────────────────┤
│ 语义分块           │ 将相关对话分组处理                            │
└────────────────────┴──────────────────────────────────────────────┘
```

## 窗口滑动：滑动上下文

最简单的记忆管理方法是只保留最近的对话轮：

```
                    ┌───────────────────────────┐
回合 1              │ 系统 + 回合 1             │
                    └───────────────────────────┘
                              │
                              ▼
                    ┌───────────────────────────┐
回合 2              │ 系统 + 回合 1-2           │
                    └───────────────────────────┘
                              │
                              ▼
                    ┌───────────────────────────┐
回合 3              │ 系统 + 回合 1-3           │
                    └───────────────────────────┘
                              │
                              ▼
                    ┌───────────────────────────┐
回合 4              │ 系统 + 回合 2-4           │ ← 回合 1 被丢弃
                    └───────────────────────────┘
                              │
                              ▼
                    ┌───────────────────────────┐
回合 5              │ 系统 + 回合 3-5           │ ← 回合 2 被丢弃
                    └───────────────────────────┘
```

这种方法简单，但会遗忘较早的信息。

## 总结压缩：压缩记忆

更高级的方法是将较早的对话轮压缩为摘要：

```
                    ┌────────────────────────────────────────────┐
回合 1-3            │ 系统 + 回合 1-3                            │
                    └────────────────────────────────────────────┘
                                       │
                                       ▼
                    ┌────────────────────────────────────────────┐
回合 4              │ 系统 + 总结(回合 1-2) + 回合 3-4            │
                    └────────────────────────────────────────────┘
                                       │
                                       ▼
                    ┌────────────────────────────────────────────┐
回合 5              │ 系统 + 总结(回合 1-3) + 回合 4-5            │
                    └────────────────────────────────────────────┘
```

摘要能保留关键信息，同时减少 token 占用。

## 键值记忆：结构化状态

为了更好地控制，可以将重要事实提取并以结构化格式存储：

```
┌─────────────────────────────────────────────────────────────────────┐
│ 上下文窗口                                                          │
│                                                                     │
│  系统提示: “You are a helpful assistant...”                         │
│                                                                     │
│  记忆:                                                              │
│  {                                                                  │
│    "user_name": "Alex",                                           │
│    "favorite_color": "blue",                                      │
│    "location": "Toronto",                                         │
│    "last_topic": "vacation plans"                                 │
│  }                                                                  │
│                                                                     │
│  最近对话:                                                          │
│  用户: “What activities would you recommend?”                       │
│  助手: “Given your location in Toronto and interest in...”          │
│                                                                     │
│  当前输入: “How about something indoors? It's cold.”                │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

这种结构化方法能精确控制保留哪些信息。

## 超越对话：有状态应用

细胞不仅能实现连贯对话，还能让 LLM 支持有状态应用：

1. 记住之前的交互
2. 更新和维护变量
3. 跟踪多步流程的进度
4. 基于先前输出继续工作

来看一个简单的计算器示例：

```
┌─────────────────────────────────────────────────────────────────────┐
│ 有状态计算器                                                        │
│                                                                     │
│ 系统: “你是一个能维护累计值的计算器助手，按用户的数学操作逐步计算。” │
│                                                                     │
│ 状态: { "current_value": 0 }                                       │
│                                                                     │
│ 用户: “Start with 5”                                                │
│ 助手: “Starting with 5. Current value is 5.”                        │
│ 状态: { "current_value": 5 }                                       │
│                                                                     │
│ 用户: “Multiply by 3”                                               │
│ 助手: “5 × 3 = 15. Current value is 15.”                            │
│ 状态: { "current_value": 15 }                                      │
│                                                                     │
│ 用户: “Add 7”                                                       │
│ 助手: “15 + 7 = 22. Current value is 22.”                           │
│ 状态: { "current_value": 22 }                                      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

状态变量在多轮对话中持续存在，实现连续计算。

1. 从对话中提取关键信息
2. 存入外部数据库
3. 需要时检索相关上下文
4. 将其纳入提示词

## 细胞实现：记忆管理器

下面是一个实现基本记忆管理的 Python 类：

```python
class ContextCell:
    """跨多轮交互维护记忆的上下文细胞。"""
    
    def __init__(self, system_prompt, max_turns=10, memory_strategy="window"):
        """
        初始化上下文细胞。
        
        参数：
            system_prompt (str): 系统指令
            max_turns (int): 保留的最大对话轮数
            memory_strategy (str): 'window'、'summarize' 或 'key_value'
        """
        self.system_prompt = system_prompt
        self.max_turns = max_turns
        self.memory_strategy = memory_strategy
        self.conversation_history = []
        self.key_value_store = {}
        
    def add_exchange(self, user_input, assistant_response):
        """添加一轮对话到历史。"""
        self.conversation_history.append({
            "user": user_input,
            "assistant": assistant_response
        })
        
        # 如有需要，应用记忆管理
        if len(self.conversation_history) > self.max_turns:
            self._manage_memory()
    
    def extract_info(self, key, value):
        """将重要信息存入键值存储。"""
        self.key_value_store[key] = value
    
    def _manage_memory(self):
        """应用选定的记忆管理策略。"""
        if self.memory_strategy == "window":
            # 只保留最近的对话轮
            self.conversation_history = self.conversation_history[-self.max_turns:]
        
        elif self.memory_strategy == "summarize":
            # 总结较早的对话轮（实际应用中会调用 LLM）
            to_summarize = self.conversation_history[:-self.max_turns + 1]
            summary = self._create_summary(to_summarize)
            # 用摘要替换旧对话
            self.conversation_history = [{"summary": summary}] + \
                                       self.conversation_history[-(self.max_turns-1):]
    
    def _create_summary(self, exchanges):
        """对对话轮进行摘要。"""
        # 实际应用中会调用 LLM 生成摘要
        # 这里用占位符
        return f"Summary of {len(exchanges)} previous exchanges"
    
    def build_context(self, current_input):
        """构建下一次 LLM 调用的完整上下文。"""
        context = f"{self.system_prompt}\n\n"
        # 如有键值记忆，加入
        if self.key_value_store:
            context += "MEMORY:\n"
            for key, value in self.key_value_store.items():
                context += f"{key}: {value}\n"
            context += "\n"
        # 加入对话历史
        if self.conversation_history:
            context += "CONVERSATION HISTORY:\n"
            for exchange in self.conversation_history:
                if "summary" in exchange:
                    context += f"[Previous exchanges: {exchange['summary']}]\n\n"
                else:
                    context += f"User: {exchange['user']}\n"
                    context += f"Assistant: {exchange['assistant']}\n\n"
        # 加入当前输入
        context += f"User: {current_input}\nAssistant:"
        return context
```

## 衡量细胞效率

如同分子，衡量细胞效率也很重要：

```
┌──────────────────────────────────────────────────────────────────┐
│ 记忆策略对比                                                    │
├──────────────────┬──────────────┬─────────────┬─────────────────┤
│ 策略             │ Token 占用   │ 信息保留    │ 实现复杂度      │
├──────────────────┼──────────────┼─────────────┼─────────────────┤
│ 无记忆           │ 最低         │ 无          │ 极易            │
├──────────────────┼──────────────┼─────────────┼─────────────────┤
│ 全历史           │ 最高         │ 完整        │ 极易            │
├──────────────────┼──────────────┼─────────────┼─────────────────┤
│ 窗口滑动         │ 可控         │ 仅最近      │ 简单            │
├──────────────────┼──────────────┼─────────────┼─────────────────┤
│ 总结压缩         │ 适中         │ 良好        │ 适中            │
├──────────────────┼──────────────┼─────────────┼─────────────────┤
│ 键值存储         │ 低           │ 选择性      │ 适中            │
├──────────────────┼──────────────┼─────────────┼─────────────────┤
│ 外部存储         │ 极低         │ 广泛        │ 复杂            │
└──────────────────┴──────────────┴─────────────┴─────────────────┘
```

不同策略适合不同需求，选择合适方法取决于具体应用场景。

│  │ • 最近对话轮    │    │ • 当前任务      │   │ • 用户档案      │   │

│  │ • 最后几轮      │    │ • 任务进度      │   │ • 偏好          │   │
│  │                 │    │ • 任务中间状态  │   │                 │   │
│  └─────────────────┘    └─────────────────┘   └─────────────────┘   │

│         │ │                   │ │                   │ │              │

│  │                    记忆管理器                             │      │
│  │                                                           │      │
│  └───────────────────────────────┬───────────────────────────┘      │
│                                  │                                   │
│                                  ▼                                   │
│                        ┌─────────────────┐                           │
│                        │                 │                           │
│                        │   上下文构建器  │                           │
│                        │                 │                           │
│                        └─────────────────┘                           │
│                                  │                                   │
│                                  ▼                                   │
│                        ┌─────────────────┐                           │

│                        │                 │                           │
│                        └─────────────────┘                           │
│                                                                     │

```

这种架构类似于人类记忆系统：
- **短期记忆**：最近的对话轮
- **工作记忆**：当前任务状态和变量
- **长期记忆**：持久的用户信息和偏好

记忆管理器负责编排这些系统，决定每次上下文包含哪些信息。

## 记忆与幻觉减少

记忆细胞的一个重要作用是减少幻觉：

```
┌─────────────────────────────────────────────────────────────────────┐
│ 幻觉减少策略                                                       │
├─────────────────────────────────────────────────────────────────────┤
│ 1. 明确存储从对话中提取的事实                                      │
│ 2. 用来源/置信度标签信息                                          │
│ 3. 相关话题时纳入相关事实                                          │
│ 4. 检测并纠正记忆与回复间的矛盾                                    │
│ 5. 定期通过用户确认重要事实                                        │
└─────────────────────────────────────────────────────────────────────┘
```

通过让 LLM 依赖一致的记忆事实，显著提升可靠性。

```

LLM 自身提取并更新需记住的重要信息，形成自我改进的记忆系统。

## 关键要点

1. **记忆细胞**让多轮交互具备状态持久性
2. **Token 配额管理**在对话增长时至关重要
3. **记忆策略**包括窗口滑动、摘要压缩、键值存储等
4. **外部记忆**实现超越上下文窗口的持久存储
5. **结构化状态**支持超越简单对话的复杂应用
6. **记忆编排**结合多种记忆系统以获得最佳表现

## 深入探讨：记忆抽象

记忆可分为多层抽象：

```
┌────────────────────────────────────────────────────────────────────┐
│ 记忆抽象层                                                        │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│   ┌─────────────────┐                                              │
│   │ 情节记忆        │  具体对话轮与事件                            │
│   └─────────────────┘                                              │
│           ▲                                                        │
│           │                                                        │
│   ┌─────────────────┐                                              │
│   │ 语义记忆        │  事实、概念、结构化知识                      │
│   └─────────────────┘                                              │
│           ▲                                                        │
│           │                                                        │
│   ┌─────────────────┐                                              │
│   │ 概念记忆        │  高层模式、偏好、目标                        │
│   └─────────────────┘                                              │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

这种分层方法让系统能在具体细节与高层理解之间取得平衡。
