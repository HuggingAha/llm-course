# 分子：结合示例的提示工程

> “整体大于部分之和。”——亚里士多德

## 从原子到分子

在上一节中，我们探讨了**原子提示**——构成 LLM 交互的基本单元的单条指令。现在我们将把这些原子组合成**分子**：包含示例和模式的结构化上下文，供模型学习和模仿。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│  分子 = [指令] + [示例] + [上下文] + [新输入]                                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

这种分子方法利用了 LLM 的一个强大能力：**少样本学习（few-shot learning）**。

## 少样本学习：以例子教学

少样本学习是指我们为模型提供期望的输入-输出模式示例，让模型能够识别并延续这种模式。

```
┌───────────────────────────────────────────────────────────────────────┐
│ 输入: "Paris"                                                         │
│ 输出: "Paris is the capital of France."                              │
│                                                                        │
│ 输入: "Tokyo"                                                         │
│ 输出: "Tokyo is the capital of Japan."                               │
│                                                                        │
│ 输入: "Ottawa"                                                        │
│ 输出: ?                                                              │
└───────────────────────────────────────────────────────────────────────┘
```

模型识别出模式并补全：“Ottawa is the capital of Canada.”

## 分子的优势：可衡量的提升

让我们比较一下原子方法和分子方法在同一任务下的表现：

```
┌───────────────────────────────────────┬─────────────────────────────────────┐
│ 原子方法                              │ 分子方法                             │
├───────────────────────────────────────┼─────────────────────────────────────┤
│ “将这条评论分类为正面或负面：         │ “对评论进行情感分类。                │
│                                       │                                      │
│  'The service was terrible and         │ 评论: 'The food was amazing!'        │
│   the food was cold.'”                 │ 情感: 正面                           │
│                                       │                                      │
│                                       │ 评论: 'Waited 30 minutes and         │
│                                       │  the food was cold.'                 │
│                                       │ 情感: 负面                           │
│                                       │                                      │
│                                       │ 评论: 'The service was terrible      │
│                                       │  and the food was cold.'”            │
│                                       │ 情感:                                │
└───────────────────────────────────────┴─────────────────────────────────────┘
```

分子方法通常能带来：
- 更高的准确率（许多任务提升 10-30%）
- 更强的一致性（输出方差更低）
- 更好的格式遵循
- 更清晰地处理边界情况

## 有效分子模板的设计

分子上下文的结构非常重要。以下是常见的模式：

```
┌───────────────────┐  ┌───────────────────┐  ┌───────────────────┐
│ 前缀-后缀         │  │ 输入-输出对       │  │ 思维链            │
├───────────────────┤  ├───────────────────┤  ├───────────────────┤
│ <指令>            │  │ <指令>            │  │ <指令>            │
│                   │  │                   │  │                   │
│ 输入: <示例1>     │  │ 输入: <示例1>     │  │ 输入: <示例1>     │
│ 输出: <结果1>     │  │ 输出: <结果1>     │  │ 思考: <步骤1>     │
│                   │  │                   │  │         <步骤2>   │
│ 输入: <示例2>     │  │ 输入: <示例2>     │  │ 输出: <结果1>     │
│ 输出: <结果2>     │  │ 输出: <结果2>     │  │                   │
│                   │  │                   │  │ 输入: <示例2>     │
│ 输入: <新输入>    │  │ 输入: <新输入>    │  │ 思考: <步骤1>     │
│ 输出:             │  │ 输出:             │  │         <步骤2>   │
└───────────────────┘  └───────────────────┘  │ 输出: <结果2>     │
                                              │                   │
                                              │ 输入: <新输入>    │
                                              │ 思考:             │
                                              └───────────────────┘
```

每种模板适合不同的任务：
- **前缀-后缀**：最简单，适合直接任务
- **输入-输出对**：结构清晰，适合结构化数据
- **思维链**：暴露推理步骤，适合复杂任务

## 示例选择的科学

并非所有示例都一样有效。为分子上下文选择示例时：

```
┌──────────────────────────────────────────────────────────────┐
│ 示例选择策略                                                │
├──────────────────────────────────────────────────────────────┤
│ ✓ 覆盖多样化案例，展示范围                                  │
│ ✓ 包含边界情况，澄清边界                                   │
│ ✓ 尽量从简单到复杂排序                                      │
│ ✓ 使用近期或常见示例（新近性和频率偏好）                   │
│ ✓ 包含“近似错误”以明确边界                                 │
└──────────────────────────────────────────────────────────────┘
```

## 衡量分子效率

随着上下文变大，token 数也会增加。让我们用实验数据衡量权衡：

```
                   [准确率]
                       ▲
                       │                  ● 4-shot
                       │
                       │              ● 3-shot
                       │
                       │          ● 2-shot
                       │
                       │      ● 1-shot
                       │
                       │  ● 0-shot
                       │
                       └────────────────────────►
                                [Token 数]
```

关键洞见：**边际收益递减**。每增加一个示例都会消耗 token，但带来的提升小于前一个。

## 寻找分子的最佳平衡点

对于大多数任务，存在一个示例数量的最佳点，兼顾质量和 token 效率：

```
┌─────────────────────────────────────────────────────────────────┐
│ 按任务类型的示例数量经验法则                                   │
├───────────────────────────┬─────────────────────────────────────┤
│ 分类                      │ 每类 1-3 个示例                     │
├───────────────────────────┼─────────────────────────────────────┤
│ 生成                      │ 2-5 个示例                          │
├───────────────────────────┼─────────────────────────────────────┤
│ 结构化抽取                │ 2-4 个示例，覆盖所有字段             │
├───────────────────────────┼─────────────────────────────────────┤
│ 推理                      │ 2-3 个带思考步骤的示例               │
├───────────────────────────┼─────────────────────────────────────┤
│ 翻译                      │ 3-5 个不同复杂度的示例               │
└───────────────────────────┴─────────────────────────────────────┘
```

## 动态分子构建

高级上下文工程会为每个输入动态选择最相关的示例：

```
┌───────────────────────────────────────────────────────────────────┐
│                                                                   │
│   用户查询                                                        │
│       │                                                           │
│       ▼                                                           │
│  ┌─────────────┐      ┌─────────────────┐                         │
│  │ 查询分析    │─────▶│ 示例数据库      │                         │
│  └─────────────┘      └─────────────────┘                         │
│                              │                                    │
│                              │ 检索最相关示例                    │
│                              ▼                                    │
│                       ┌─────────────────┐                         │
│                       │ 动态分子上下文  │                         │
│                       └─────────────────┘                         │
│                              │                                    │
│                              ▼                                    │
│                       ┌─────────────────┐                         │
│                       │                 │                         │
│                       │ LLM             │                         │
│                       │                 │                         │
│                       └─────────────────┘                         │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
```

这种方法：
1. 分析用户查询
2. 检索最相关的示例
3. 构建定制化的分子上下文
4. 将优化后的上下文发送给 LLM

## 实践：一个简单的实现

下面是一个用 Python 构建分子上下文的函数：

```python
def create_molecular_context(instruction, examples, new_input, 
                            format_type="input-output"):
    """
    从示例构建分子上下文。
    
    参数：
        instruction (str): 任务指令
        examples (List[Dict]): 示例输入/输出对列表
        new_input (str): 新输入
        format_type (str): 模板类型（input-output, chain-of-thought）
    
    返回：
        str: 完整的分子上下文
    """
    context = f"{instruction}\n\n"
    
    # 根据模板类型添加示例
    if format_type == "input-output":
        for example in examples:
            context += f"Input: {example['input']}\n"
            context += f"Output: {example['output']}\n\n"
    elif format_type == "chain-of-thought":
        for example in examples:
            context += f"Input: {example['input']}\n"
            context += f"Thinking: {example['thinking']}\n"
            context += f"Output: {example['output']}\n\n"
    
    # 添加新输入
    context += f"Input: {new_input}\nOutput:"
    
    return context
```

## 关键要点

1. **分子上下文**将指令与示例结合，提升 LLM 表现
2. **少样本学习**让模型识别并延续模式
3. **模板结构**很重要，不同格式适合不同任务
4. **示例选择**有讲究，多样性、边界和排序都很关键
5. **边际收益递减**，每增加一个示例带来的提升会减少
6. **动态构建**可为每个输入优化上下文

## 练习

1. 针对一个简单分类任务，分别用 0、1、3、5 个示例测量表现
2. 在同一任务上比较不同模板结构
3. 实现基于与新输入相似度的动态示例选择
4. 为你关心的任务找到“最小可行分子”

## 深入探讨：提示工程 vs. 上下文工程

提示工程关注于打造完美的指令。上下文工程则包含更多层次：

```
┌─────────────────────────────────────────────────────────────────────┐
│ 上下文工程的层次                                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   ┌─────────────────┐                                               │
│   │ 状态与记忆      │  对话历史、持久变量                           │
│   └─────────────────┘                                               │
│           ▲                                                         │
│           │                                                         │
│   ┌─────────────────┐                                               │
│   │ 检索数据        │  RAG、工具输出、外部知识                      │
│   └─────────────────┘                                               │
│           ▲                                                         │
│           │                                                         │
│   ┌─────────────────┐                                               │
│   │ 示例            │  少样本学习、演示                             │
│   └─────────────────┘                                               │
│           ▲                                                         │
│           │                                                         │
│   ┌─────────────────┐                                               │
│   │ 指令            │  提示、系统消息、约束                         │
│   └─────────────────┘                                               │
│           ▲                                                         │
│           │                                                         │
│   ┌─────────────────┐                                               │
│   │ 模型行为        │  训练数据、对齐、能力                         │
│   └─────────────────┘                                               │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

上下文工程让你能掌控更多层次，从而打造更强大的应用。
