# 原子：提示工程的基本单元

> “如果你想从零开始做一个苹果派，你必须先创造宇宙。”——卡尔·萨根

## 原子：单一指令

在我们的上下文工程之旅中，我们从最基本的单元开始：**原子**——对LLM的单一、独立指令。

```
┌───────────────────────────────────────────────┐
│                                               │
│  “写一首关于大海的四行诗。”                  │
│                                               │
└───────────────────────────────────────────────┘
```

这就是最纯粹的提示工程：一个人，一条指令，一个模型响应。简单、直接、原子化。

## 原子提示的结构

让我们拆解一下什么是有效的原子提示：

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  原子提示 = [任务] + [约束] + [输出格式]                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

例如：

```
┌─────────────────────┬────────────────────────┬────────────────────┐
│        任务         │      约束              │   输出格式         │
├─────────────────────┼────────────────────────┼────────────────────┤
│ “写一首关于太空的诗”│ “只用5个字母的单词”    │ “四行诗。”         │
│                     │                        │                    │
└─────────────────────┴────────────────────────┴────────────────────┘
```

## 原子的局限性

虽然原子提示是LLM交互的基石，但它们很快就暴露出一些根本性局限：

```
┌──────────────────────────────────────┐
│ 原子提示的局限性                     │
├──────────────────────────────────────┤
│ ✗ 交互间无记忆                       │
│ ✗ 演示能力有限                       │
│ ✗ 无复杂推理支架                     │
│ ✗ 易产生歧义                         │
│ ✗ 输出结果波动大                     │
└──────────────────────────────────────┘
```

让我们用一个简单实验来实证：

```python
# 一个基础的原子提示
atomic_prompt = "列举5个糖尿病症状。"

# 多次发送给LLM
responses = [llm.generate(atomic_prompt) for _ in range(5)]

# 测量多样性
unique_symptoms = set()
for response in responses:
    symptoms = extract_symptoms(response)
    unique_symptoms.update(symptoms)

print(f"5次相同提示共发现{len(unique_symptoms)}种独特症状")
# 通常输出的独特症状远超5个
```

问题是什么？即使是同样的原子提示，每次得到的回复也不同。模型在最小上下文下难以保持一致性。

## 单原子基线：有用但有限

尽管有局限，原子提示为我们建立了基线。它们帮助我们：

1. 测量token效率（最小开销）
2. 基准响应质量
3. 为实验建立对照

```
                     [响应质量]
                            ▲
                            │
                            │               ⭐ 上下文
                            │                 工程
                            │               
                            │           ⭐ 高级
                            │             提示
                            │
                            │   ⭐ 基础提示
                            │
                            │
                            └────────────────────────►
                                  [复杂度]
```

## 未言明的上下文：模型已“知”的内容

即使是原子提示，LLM也会利用其训练中获得的大量隐式上下文：

```
┌───────────────────────────────────────────────────────────────┐
│ 模型中的隐式上下文                                            │
├───────────────────────────────────────────────────────────────┤
│ ✓ 语言规则与语法                                             │
│ ✓ 常识性事实                                                 │
│ ✓ 格式约定（列表、段落等）                                   │
│ ✓ 领域知识（因模型而异）                                     │
│ ✓ 学到的交互模式                                             │
└───────────────────────────────────────────────────────────────┘
```

这些隐式知识为我们提供了基础，但它不可靠，并且在不同模型和版本间有所差异。

## 幂律：Token-质量曲线

对于许多任务，我们观察到上下文token数量与输出质量之间存在幂律关系：

```
    质量
      ▲
      │    •
      │        •
      │            •
      │                •
      │                    •
      │                        •         •         •
      │                             
      └───────────────────────────────────────────► Token数
                                      
          [最大回报区]           [收益递减区]
```

关键洞见：存在一个“最大回报区”，在这里仅增加少量token就能显著提升质量。

## 从原子到分子：对更多上下文的需求

原子的局限性自然引导我们进入下一步：**分子**，即将指令与示例、额外上下文和结构化格式结合的多部分提示。

基本转变如下：

```
┌──────────────────────────┐         ┌──────────────────────────┐
│                          │         │ “这里有个例子：           │
│ “写一首关于程序员的打油诗。”│    →    │  从前有个……             │
│                          │         │                          │
└──────────────────────────┘         │  现在请写一首关于程序员的打油诗。”│
                                     └──────────────────────────┘
    [原子提示]                           [分子提示]
```

通过添加示例和结构，我们开始有意识地塑造上下文窗口——这就是上下文工程的第一步。

```
└─────────┴───────────────────────────────┴────────┴──────────┘
```

## 关键要点

1. **原子提示**是LLM交互的基本单元
2. 它们遵循基本结构：任务+约束+输出格式
3. 存在固有限制：无记忆、无示例、无推理支架
4. 即使简单原子提示也会利用模型的隐式知识
5. 上下文token与质量呈幂律关系
6. 超越原子是迈向上下文工程的第一步
