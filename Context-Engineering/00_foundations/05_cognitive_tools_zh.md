## 什么是认知工具？

### **[Eliciting Reasoning in Language Models with Cognitive Tools - IBM Zurich 2025年6月](https://www.arxiv.org/pdf/2506.12115)**

### 提示与提示程序作为推理工具调用
> “认知工具”将推理操作封装在 LLM 内部——[IBM Zurich](https://www.arxiv.org/pdf/2506.12115)

> 这些认知工具（结构化提示模板作为工具调用）通过识别主要概念、提取问题中的关键信息、突出有用的属性、定理和技巧，将问题分解，有助于解决问题。

> 这些模板为推理层搭建脚手架，类似于心理学中常见的“启发式”捷径。

## 提示程序：LLM 的算法化思维（推理工具调用）

提示程序是一种结构化、可复用的提示模式，用于引导 LLM 的推理过程——类似于启发式引导人类思考。

### 从临时提示到程序化模式

对比临时提示与简单提示程序（推理工具调用）：

```
┌───────────────────────────────────────────────────────────────┐
│ 临时提示                                                      │
├───────────────────────────────────────────────────────────────┤
│ “用三段话总结这篇气候变化文章，要求通俗易懂。”               │
└───────────────────────────────────────────────────────────────┘

┌───────────────────────────────────────────────────────────────┐
│ 提示程序                                                      │
├───────────────────────────────────────────────────────────────┤
│ program Summarize(text, paragraphs=3, complexity="simple") {  │
│   // 定义任务                                                 │
│   task = `用${paragraphs}段话总结下文，语言风格为${complexity}`; │
│   // 定义流程                                                 │
│   process = ```                                              │
│     1. 找出主题和要点                                        │
│     2. 按重要性组织要点                                      │
│     3. 结构化输出：                                          │
│        - 第一段：主题与背景                                  │
│        - 中间段：关键细节                                    │
│        - 结尾段：结论或影响                                  │
│   ```;                                                       │
│   // 定义输出格式                                            │
│   format = "${paragraphs}段总结，风格：${complexity}";         │
│   // 构建完整提示                                            │
│   return `${task}\n\n流程:\n${process}\n\n格式:\n${format}\n\n待总结文本:\n${text}`; │
│ }                                                            │
└───────────────────────────────────────────────────────────────┘
```

提示程序的优势：
1. **可复用性**：同一模式可用于不同文本
2. **参数化**：可灵活定制长度、难度等
3. **透明性**：结构清晰，意图明确
4. **一致性**：输出更可控

### 简单提示程序模板

```
program [Name]([parameters]) {
  // 定义任务
  task = `[用参数写清楚指令]`;
  // 定义流程
  process = ```
    1. [第一步]
    2. [第二步]
    3. [更多步骤]
  ```;
  // 定义输出格式
  format = "[期望的回复结构]";
  // 构建完整提示
  return `${task}\n\n流程:\n${process}\n\n格式:\n${format}\n\n[输入]`;
}
```

实际应用中，这一模板可用伪代码、JS/Python 生成函数、YAML/JSON 模板等多种方式实现。

## 什么是协议壳？（推理工具调用）

协议壳是一种结构化无代码模板，将与 AI 的沟通组织为清晰一致的模式。它类似对话蓝图，包含：
1. **意图**：目标是什么
2. **输入**：你提供了什么信息
3. **流程**：如何处理信息
4. **输出**：你期望什么结果

### 协议壳基本结构

```
/protocol.name{
    intent="目标说明",
    input={
        param1="值1",
        param2="值2"
    },
    process=[
        /step1{action="做某事"},
        /step2{action="做另一事"}
    ],
    output={
        result1="期望输出1",
        result2="期望输出2"
    }
}
```

这种结构为你和 AI 提供了清晰、高效的沟通框架。

**思考练习**：回顾你最近的 AI 对话，能否发现你隐含使用的结构？如果将其正式化为协议壳，是否能提升交互效果？

## 上下文图式：结构化信息模式

正如人脑用图式组织知识，我们也可以为 LLM 构建上下文图式——标准化结构，提升模型理解。

### 基本图式结构

```
┌───────────────────────────────────────────────────────────────┐
│ 上下文图式                                                    │
├───────────────────────────────────────────────────────────────┤
│ {                                                             │
│   "$schema": "context-engineering/schemas/v1.json",           │
│   "title": "分析请求图式",                                    │
│   "description": "分析请求的标准格式",                        │
│   "type": "object",                                           │
│   "properties": {                                             │
│     "task": {                                                 │
│       "type": "string",                                       │
│       "description": "要执行的分析任务"                        │
│     },                                                        │
│     "context": {                                              │
│       "type": "object",                                       │
│       "properties": {                                         │
│         "background": { "type": "string" },                   │
│         "constraints": { "type": "array" },                   │
│         "examples": { "type": "array" }                       │
│       }                                                       │
│     },                                                        │
│     "data": {                                                 │
│       "type": "string",                                       │
│       "description": "待分析信息"                              │
│     },                                                        │
│     "output_format": {                                        │
│       "type": "string",                                       │
│       "enum": ["bullet_points", "paragraphs", "table"]        │

│   "required": ["task", "data"]                                │

```

> “我们的结果表明，推理驱动的记忆整合为训练长时序交互智能体提供了可扩展的新方案，兼顾效率与性能。”——[Singapore-MIT](https://arxiv.org/pdf/2506.15841)

### 从图式到提示

图式可通过填充结构化模板转化为实际提示：

```
# 分析请求

## 任务
找出文本中的主要主题和支撑证据。

## 上下文
### 背景
这是一场2023年气候大会的演讲。

### 约束
- 只关注科学论断
- 忽略政治表述
- 保持中立

### 示例
- 主题：海平面上升
  证据：“测量显示2010年以来每年上升3.4毫米”

## 数据
[此处为演讲全文]

## 输出格式
bullet_points
```

这种结构化方式让模型明确知道输入和期望输出。

## 递归提示：自我改进

递归提示类似认知启动效应——通过建立模式影响后续行为。核心思想是让模型反思并改进自身输出。

### 基本递归模式

```
┌───────────────────────────────────────────────────────────────┐
│ 递归提示流程                                                 │
│                                                               │
│  ┌─────────────┐      ┌─────────────┐      ┌─────────────┐    │
│  │             │      │             │      │             │    │
│  │  初始回复   │─────►│  自我反思   │─────►│  改进回复   │    │
│  │             │      │             │      │             │    │
│  └─────────────┘      └─────────────┘      └─────────────┘    │
│        ▲                                          │           │
│        └──────────────────────────────────────────┘           │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

### 简单实现

```python
def recursive_prompt(question, model, iterations=2):
    """递归提示提升回复质量。"""
    # 初始回复
    response = model.generate(f"Question: {question}\nAnswer:")
    for i in range(iterations):
        reflection_prompt = f"""
        Question: {question}
        Your previous answer: 
        {response}
        请反思你的答案：
        1. 有哪些信息可能遗漏？
        2. 有哪些假设需要质疑？
        3. 如何让解释更清晰或更准确？
        现在，给出改进后的答案：
        """
        response = model.generate(reflection_prompt)
    return response
```

这种递归模式能显著提升模型输出质量。
